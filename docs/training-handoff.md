## 另一台电脑怎么使用

先把这些改动提交并 push 到 GitHub，再在训练电脑拉取。首次使用先 clone 仓库；已有仓库就在 Nabu 文件夹中执行：

```sh
git pull --ff-only origin main
```

训练电脑需要原生 Apple Silicon macOS 的 Python 3.14。准备入口使用 `python3.14`；如果安装位置不同，可以设置 `NABU_PYTHON` 为 Python 3.14 的可执行文件路径。不要用 Intel/Rosetta 的 Python。仓库提供本次实际测试环境的 99 个依赖版本，安装不需要 API key。

```sh
bash scripts/prepare-epoch1.sh --calibrate-gpu
```

这一步会建立环境，检查训练和外部测试数据，下载固定版本的 Qwen3-8B 并转换为 MLX 4-bit，验证全部 60 条的完整长度和答案训练位置，再检查 Metal。`--calibrate-gpu` 额外用随机数字做两次硬件试算和临时适配器保存检查，结果随即丢弃；它不用工单数据训练模型，不会产生正式训练结果。若暂时只做环境、数据和 Metal 检查，省略这个选项即可。

第一次需要网络、较长下载时间和足够磁盘空间，建议为源模型、转换后的模型、缓存及环境留至少 40GB 空闲。模型权重不放在 Git 中；脚本从固定来源版本下载。运行日志在本机 `data/training/local-preflight.*`，不会混入要 push 的数据。

检查通过后，**由你决定何时执行下面这一条，它才开始正式微调**：

```sh
bash scripts/start-epoch1.sh data/training/run-epoch1
```

换一轮训练时换一个新的输出目录；脚本拒绝覆盖旧训练结果。也可使用原来的两个参数形式：`bash scripts/start-epoch1.sh REVIEWED_DATASET NEW_RUN_DIRECTORY`。相对路径从仓库根目录计算，仓库目录含空格也支持。

## 已固定的设置和可用性

使用 `Qwen/Qwen3-8B`，来源提交 `b968826d9c46dd6066d109eabc6255188de91218`，MLX 4-bit、LoRA rank 16、batch 1、学习率 0.0001、只训练一轮、8192 token 上限、只计算答案的损失、关闭 thinking、固定 seed 3407。本次原始 tokenizer 检查最大 6547 token，60 条都无需额外截断，答案前缀检查全部通过。实际 58 次样本迭代的梯度累积为 2，产生 29 次更新；这是为了让每条数据只用一次并完整应用最后的梯度。

另一台电脑直接读仓库中的 JSONL 和审计证明即可，不需要原来的 SQL、SQLite、原电脑账号路径或重新生成标签。旧 provenance 中的绝对路径仅描述历史来源，运行入口不使用这些路径。训练入口会重新验证文件、审核记录、时间分割、引用、输入校验值和模型来源版本。

已经在不带原数据库、模型及虚拟环境的临时仓库副本中验证了两个数据包检查入口。训练电脑的实际模型转换和 GPU 试算仍需在那里完成；本次没有启动正式训练，也没有声称训练电脑已经跑通完整模型。

## 测试数据和结论边界

`data/external-test/mesos-ai-reference-v1` 包含原先固定抽样的 32 条 Mesos 历史输入与逐条审核的参考答案，其中 3 条为条件性 validation 风险。它们只用于训练结束后的比较，不能加入训练、选择训练参数或调整提示词。它们也是 AI 参考，不是独立人工判定的真实事故答案。历史导入中不确定的状态、类型和链接映射保持明确未知，没有猜测填充。

当前 2 条 XD 验证数据没有风险答案，因此不能估计风险召回率；训练没有 `scope_gap` 的正例。只有 3 条训练风险，模型可能倾向返回空风险。现有数据支持第一次小规模实验，无法据此宣布模型可靠或用于正式项目决策。公司影响等级、置信度和真实业务表现尚未验证；不要把一般的 medium 标注当作已校准的公司风险等级。

训练完成后再比较未微调模型和适配器在相同冻结输入上的表现，包括格式、引用、条件性建议是否有根据、误报及漏报。部署前还需评估最终量化模型。32 条 Mesos 参考不会弥补 XD 验证集中缺少正例的问题；原 XD 时间末段测试集继续保留。

Mesos 的冻结输入最长为 12577 token，评测服务需要至少 16384 token 的上下文，并将最大回答设为 2048 token；不要用 8192 的服务窗口静默截断这些输入。这个容量要求来自输入长度检查，尚未验证模型在这些较长输入上的质量。API 的传输上限可明确设为 128000 bytes；原评测入口默认的 24000 bytes 太小。
